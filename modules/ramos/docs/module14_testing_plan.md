# Ramos Module 14 – Final Testing & Launch Plan

## 1. Scope & Objectives
- Validate the full Ramos lifecycle from client portal order intake through invoicing, purchasing, picking, routing, and dashboard/notification fan-out.
- Confirm pricing data integrity (Module 12), realtime updates (Module 10), and the new dashboard/notification center introduced in Module 13.
- Establish repeatable data sets + scripts so QA, client UAT, and production smoke-tests all run from the same checklist.

## 2. Test Data & Environment Prep
| Area | Required Data | Seeder/Notes |
| ---- | ------------- | ------------ |
| Customers | ≥3 Perfex clients with linked contacts (portal access) | Use existing CRM records or `clients_model` importer. |
| Price Lists | Price rules for each (customer, inventory item) combination under test | Create via `admin/ramos/pricing` UI or insert into `tblramos_price_rules`. |
| Inventory | 20+ SKUs with safety stock and supplier links | Maintain via `admin/ramos/inventory`; ensure at least 5 items are below/near safety stock to exercise low-stock alerts. |
| Orders | Manual + portal + CSV imports covering all statuses (new/processing/ready) and priorities | Use `admin/ramos/orders`, portal at `clients/ramos_client/orders`, and importer; tag some orders with delivery date/time for routing. |
| Picking Modules | Define all four modules, assign products, and start shifts for two staff | `admin/ramos/picking`; capture staff IDs for audit. |
| Purchases | Generate at least 2 batches (sent/partial) with receipts | `admin/ramos/purchases`; leave one batch “sent” for delay testing. |
| Routes | Autogenerated + manually adjusted routes using Kanban board | `admin/ramos/routes` + `/routes/board`; ensure at least one delayed route by setting start time in the past. |

## 3. End-to-End Flow Checklist
1. **Portal Intake → Manual Review**
   - Client contact submits order (single + CSV).
   - Admin verifies order auto-tags (`customer_reference`, `client_id`) and pricing assignment warnings.
2. **Order Items → Inventory Impact**
   - Add items, ensure picking tasks created (`ramos_picking_tasks`).
   - Adjust inventory; confirm safety status badges update.
3. **Picking Console**
   - Start shifts, pick/weight items, mark partial and complete to drive Module 10 updates.
4. **Purchase Planning & Receipts**
   - Run deficit planner, approve batches, send + partially receive items (watch live inventory adjustments).
5. **Pricing & Invoicing**
   - Move orders to READY, verify invoices auto-create with correct rates/discounts and appear in orders table.
6. **Routes & Kanban**
   - Generate daily routes, drag/drop stops, mark statuses, confirm freight color indicators + background notifications.
7. **Dashboard & Notifications**
   - Observe metric tiles, low-stock alerts, PO delays, route delays, and order-created feed entries update during workflow.

## 4. Regression Buckets
- **Data Integrity:** order numbers uniqueness, invoice linkage, safety stock math, purchase receipts updating quantities.
- **Permissions:** staff_can checks on each controller (`Orders`, `Inventory`, `Picking`, `Routes`, `Ramos`).
- **Live Updates:** picking console auto-refresh, routes board polling, dashboard polling (15s) & CSRF refresh on notification actions.
- **Notifications:** creation + resolution for new orders, delayed routes, delayed purchases; acknowledgement endpoints return updated CSRF tokens.

## 5. Issue Logging
- Track defects in shared sheet or Perfex task list with fields: module, reproduction steps, expected vs actual, blocking severity, fix owner, verification date.
- Capture DB snapshots (mysqldump) before/after each major fix for quick rollback.

## 6. Exit Criteria
- All flows above executed twice (QA + client witness) with zero outstanding blockers.
- Dashboard snapshot CLI (see `modules/ramos/controllers/Ramos_testing.php`) returns `status: "ok"` for two consecutive runs 15 minutes apart.
- Daily backup + rollback doc reviewed by client, cron jobs (polling/websocket + optional notifier) validated on staging.

## 7. Automation & Helper Commands
| Purpose | Command | Notes |
| ------- | ------- | ----- |
| Dashboard/notification health-check | `php index.php ramos/ramos_testing snapshot [YYYY-MM-DD]` | Non-zero exit status indicates warnings; logs summary via `log_message('info', ...)`. Wire this into CI/CD or cron during UAT week. |
| Perfex DB backup (built-in) | `php index.php cron db_backup` | Ensure `db_backup` cron is configured and verify archive in `/application/backup`. |
| Cache clear after deployments | `php index.php cron clear_cache` | Prevent stale dashboard translations/JS. |

## 8. Deployment & Rollback Readiness
1. **Pre-Deploy Checklist**
   - Confirm `.env`/config settings for WhatsApp/email gateways (Module 5) and cron frequency (Module 10 polling) match production expectations.
   - Take manual DB snapshot (`mysqldump perfex > backup.sql`) in addition to Perfex automated backup.
   - Export `/modules/ramos` directory to versioned artifact; capture git hash from CLI if repository is under VCS elsewhere.
2. **Deployment Steps**
   - Upload updated module files, run Perfex “Update Database” from Utilities to execute `modules/ramos/install.php` (ensures `ramos_notifications` table).
   - Clear browser + server caches, then run `php index.php ramos/ramos_testing snapshot` to confirm environment health before opening to staff.
3. **Rollback Plan**
   - Restore DB from snapshot, redeploy prior `/modules/ramos` package, flush cache.
   - Run snapshot command again to confirm consistent metrics.
4. **Cron & Monitoring**
   - Ensure existing cron hitting `php index.php cron` continues every 5 min; add optional cron for the snapshot command (write output to log + send email on warnings).
   - Document how to acknowledge/resolve notifications via dashboard (so operations can silence processed alerts).
